# Release Notes — 2026-07-28

## Summary

Process session — **no code in this repository changed.** All work landed in the global Claude Code configuration (`~/CLAUDE.md`, `~/.claude/settings.json`, `~/.claude/hooks/`), which governs how every FC in this project gets planned, built, and reviewed. Recorded here because the rules that ship this repo's code changed materially.

Three things happened. The **model lineup was assigned to workflow stages** (plan → Fable, build → Opus, adversarial review → Fable). **Two adversarial reviews became the hard floor for every plan-driven PR**, replacing the previous one-reviewer-for-routine / two-for-high-stakes tiering. And because doc-only guidance was judged insufficient to guarantee adherence, a **PreToolUse hook now enforces the model rules** at tool-call time.

The session's one genuine discovery was that the obvious way to implement that hook is wrong: `settings.json`'s `model` key is not the live session model.

## Changes

### Process — `~/CLAUDE.md`

- **§1 Communication Style** split into *Brevity and structure* and *When to critique*.
  - New default: concise, bulleted, lead with the answer, no preamble. Guarded explicitly — "brevity is never an excuse to omit"; compress prose, not substance; ties resolve toward *clearer*.
  - New rule: **a question is an invitation to research and respond critically**, not a directive to execute. Covers literal question marks and opinion/recommendation requests. The pre-existing rule only covered proposed directions ("lets do X"), which left plain questions ambiguous.

- **§2 Workflow** gained a **Model assignment** table (plan/build/review/confirmation → model + rationale) with four enforcement rules: set `model` explicitly on every subagent and never inherit; flag session-model mismatches to the user since they cannot be fixed mid-turn; fresh context is a requirement *separate* from model choice; deviations only on explicit request.

- **Peer review tightened to a hard gate.** Two adversarial reviews per plan-driven PR, fresh context each, both on Fable, different personas, **run concurrently so neither sees the other's findings**. Findings are the **union** of both; merge requires APPROVE from both; reviewer-vs-reviewer disagreement escalates to the user rather than being adjudicated by the author.

- **Stakes calibration rewritten.** It previously *was* the mechanism that added a second reviewer. With two as the floor, high-stakes now escalates persona sharpness and live-production-data verification instead of reviewer count. Confirmation pass stays at one reviewer, checking against the combined fix list.

- **§5 Plan-First** gained *Who writes the plan, who builds from it*, which turns the plan file into an explicit **handoff contract**: exact files/functions, behavior contract, decisions-with-rationale (so the builder does not relitigate), test requirements, and flagged blocking vs. non-blocking open questions. A plan that is not handoff-ready is a plan bug, fixed before code.

### Tooling — `~/.claude/hooks/model-stage-check.sh`

New `PreToolUse` hook, wired in `~/.claude/settings.json` on matcher `Write|Edit|NotebookEdit|Agent|Task`.

| Trigger | Check | On mismatch |
| --- | --- | --- |
| `Agent` spawn whose prompt reads as a review | `model` param must be Fable | **Permission prompt** |
| Write/Edit to `docs/plans/fc-*.md` | session model should be Fable | Non-blocking warning |
| Write/Edit to `src/` `app/` `lib/` | session model should be Opus | Non-blocking warning |

Fails open by design — unreadable transcript, missing `jq`, or unrecognized payload exits 0 silently.

## Key Decisions & Rationale

- **Read the live model from the transcript, not `settings.json`.** The natural implementation checks the `model` key in settings. That is wrong: this machine's `~/.claude/settings.json` pins `claude-fable-5[1m]`, while the session doing this work ran `claude-opus-5`. `settings.json` holds the *configured default*, which `/model` or a CLI flag overrides for the running session. A settings-based check would have been wrong in 100% of observed cases. The hook instead reads the last `"model":"..."` from `~/.claude/projects/<sanitized-cwd>/<session_id>.jsonl`.

- **Gate reviews, warn on file writes.** Considered three enforcement strengths (warn-everything / split / gate-everything). Split was chosen because the false-positive profiles differ sharply. `docs/plans/fc-*.md` is edited for *bookkeeping* — status flips, Execution-section backfill — about as often as for authoring, and a path alone cannot distinguish them, so a gate there would prompt constantly on legitimate work. A review agent silently inheriting the session model, by contrast, is **never** correct, and the spawn is rare enough that a prompt costs nothing. Gate-everything was rejected as the option most likely to be disabled out of annoyance, which would leave zero enforcement.

- **Two reviewers for everything, accepting the cost.** This roughly doubles review spend on routine M/L changes. Justified by this project's own track record: the 2026-05-08 FC-029 session had a second reviewer catch 4 HIGH + 3 MEDIUM findings the first reviewer missed, and FC-043 (2026-07-24) had the two-reviewer process catch a mis-scoped poll path. The empirical hit rate for "second reviewer finds something real" has been high enough that tiering was costing more in escaped defects than it saved in tokens.

- **The hook is a safety net, not the source of truth.** `~/CLAUDE.md` remains authoritative. The hook fails open on every ambiguity, on the principle that a check which blocks work because it could not determine the model is worse than no check.

## Outstanding

- **`~/CLAUDE.md` has no version control and no backups.** 26KB of process refined over many sessions, in a single unbacked file; `~/.claude/settings.json` and the new hook script are equally unprotected. Home directory is not a git repo. Proposed fix — a private dotfiles repo with the three paths symlinked in — was raised and not yet actioned. **Severity: medium-high**; the loss is unrecoverable and today's edits were substantial.

- **The hook's review gate has not fired live.** Only the `Write`/`Edit` branch was proven end-to-end. The `Agent` branch was validated against synthetic payloads, with field names `tool_input.prompt` and `tool_input.model` inferred from the Agent tool schema rather than observed. The first real adversarial review spawn is the live test — **if no permission prompt appears when spawning a reviewer without `model: "fable"`, the field names are wrong.** Severity: low, fails open.

- **The review gate keys off prompt wording** (`adversarial`, `request_changes`, `peer review`, `reviewer`, `blocker`). The standard review template in `~/CLAUDE.md` contains several, so it is covered in practice — but rewording that template to avoid all of them would silently disable the gate with no error.
