# Release Notes — 2026-07-29

## Summary

The backtest engine is **landed as a measurement tool**. The session's defining finding is
that **every backtest this project had ever run modelled a put-only wheel** — covered calls
were misrouted and silently rejected (FC-048). Fixing that, then re-validating everything
downstream, revealed that the dominant constraint on this strategy is **configuration, not
engine fidelity**: a `$400` price ceiling and a `$0.50` premium floor between them exclude
**8 of 14 configured symbols**.

Programmatic demotion was explicitly deferred by the owner — the engine ships as a
measurement instrument, and `demote` remains a column rather than a trigger.

23 commits, 11 PRs merged (#55–#65), 13 FCs filed (FC-045 → FC-057).

## Changes

### New Features

- **Call-side parity measurement** (`parity_check.py --side call`) — the engine's other half
  had never been measured. Resolves the cost-basis floor per FC-029 R2 from the assigning
  put, so the comparison asks the question live actually answered.
- **`docs/BACKTEST_ENGINE.md`** — the handoff doc: what the engine measures well, what it
  does not, the six traps for readers, and a re-runnable derivation for every number.
- **Stage-1 rejections are now reportable** (FC-057) — a symbol blocked on the price/volume
  band names its constraint instead of showing an unexplained `insufficient`.
- **`strict_option_type()`** in `src/utils/option_symbols.py` — a fully-anchored OCC parser
  for use anywhere the answer decides *which order gets placed*.
- **RTH-gated spread measurement** — `spread_model_check.py --require-rth` refuses to emit
  a conclusion when the market is closed.

### Bug Fixes

- **FC-048 — the backtest ran half a wheel.** `ExecutionEngine` routed on
  `opp.get('type', 'put')`. Only the scanner sets `'type'`; the sellers set `'strategy'`.
  Every seller-produced covered call defaulted to "put", went to `put_seller`, and was
  rejected by its wrong-seller guard. Production unaffected (it executes scanner-shaped
  dicts). Fixed by routing on a strict OCC parse and failing loud — *not* by patching the
  producer, because the permissive default was the trap.
- **FC-045 — `/monitor` misrouted covered calls.** `is_put = 'P' in symbol` tested the
  ticker's own letters, so AAPL/SPY/PFE calls ran put-close logic and were tagged
  `position_type='PUT'`.
- **FC-052 — oversell guard counted short puts as committed calls.** `'C' in opt_sym` over a
  hand-rolled underlying; a short put on a C-containing ticker consumed call capacity and
  silently starved the call side. Latent (no configured symbol contains a C).
- **FC-035 — deleted the dead `poll_order_statuses` path** and the `order_statuses` table
  (0 rows, 0 readers, 0 views, 0 scheduled queries — all verified live pre-build).
- **FC-036 Phase A — the stage-4 gap gate read today's own bar.** Alpaca stamps daily bars
  at midnight ET, so a timestamp comparison admitted the current session's partial bar as
  "previous close". Shipped with correct math but **unarmed**.
- **CLI errors were invisible** — `main()` logged and `sys.exit(1)` without printing, so a
  failed backtest showed its banner then silence, hiding a diagnostic that named the exact
  fix.
- **Conftest gap thresholds were in the wrong units** (fractions where the code uses
  percent).

## Key Decisions & Rationale

**Route on the OCC symbol, not on a dict key (FC-048 D1).** The three-line fix — add
`'type': 'call'` to the producer — was rejected. It fixes the instance and leaves
`opp.get('type', 'put')` in place, so a missing key still silently means "put" and the next
producer recreates the bug invisibly. Rejected also: routing on `'strategy'` (the scanner
never sets it, so it would misroute *production*), and a validated `Opportunity` dataclass
(right long-term, an M-sized refactor across four producers, and it would delay the
re-validation which was the actual deliverable).

**Strict parse, not the canonical parser's lenient path.** A reviewer showed
`parse_option_symbol` resolves bare `'AAPL'` → *put* and `'NOT_AN_OCC'` → *call* via a
`'C' in symbol` fallback. Routing a bare ticker to `put_seller` means
`place_option_order('AAPL', …)` — a plain **equity** order. Hence `strict_option_type()`.
Adjusted roots (`1AAPL…`) are refused deliberately: their deliverable is not 100 shares, so
collateral and cost-basis math would be wrong.

**FC-036 ships unarmed, and Phase B is withdrawn rather than deferred.** The study found
that arming the corrected gate at 1.5 costs a net **−$5,021** against 330 real fills — 24% of
ten months' realized P&L — while genuinely avoiding 10 of 29 assignments. At 3.5+ it blocks
only winners. A control that is *directionally right about risk but wrong about cost at every
setting* is **mis-shaped, not mis-tuned**; a fixed percentage cliff is the wrong instrument.

**FC-035: delete rather than revive.** Both PR #47 reviewers independently argued deletion.
Deciding factors: zero readers (verified against live `INFORMATION_SCHEMA`, not greps), and
FC-012 had **already scheduled this exact `bq rm`** in April via a cleanup that never ran.
Deletion completes a recorded decision rather than making a new one.

**Every study required a real-fills layer, not just engine A/B.** This is the decision that
paid off most. FC-036's engine A/B called threshold 5.0 "free"; the real-fills join proved it
was a $1,900 tax that prevented nothing. Because all three studies rested on real fills,
**every headline verdict survived the FC-048 engine change** — DO-NOT-ARM, don't-re-tune,
DEMOTE.

**The screen was run `--no-persist`.** The first *persisted* post-fix screen writes to a
canonical table that historically drove demotion recommendations; that should be a deliberate
decision, not a side effect of re-validation.

## Discoveries

- **The engine's honesty about itself was consistently weaker than its arithmetic.** Four
  instances: the "81% strike reproduction" headline was **put-leg only**; the call leg had
  never been measured; ex-div early assignment was described as "modeled" having **never once
  executed**; and stage-1 exclusions reported `insufficient` with **no reason**. None produced
  a wrong number — all produced **missing explanations**, and the reader supplies their own.
- **The $400 `max_stock_price` ceiling excludes SPY ($736), QQQ ($671) and AMD ($442)** at
  stage 1, and MSFT ($395) oscillates on it. Combined with the premium floor excluding
  F/PFE/KMI/VZ, the **effective universe is 6 of 14**. This is why FC-057 matters: the engine
  could not say so.
- **The stage-2 gap-risk filter has never gated a live trade** (FC-049). It is reachable only
  via `run_strategy_cycle()`, which no deployed endpoint calls — `/run` moved to
  `OpportunityStore` + `ExecutionEngine` in `842dcce`, three days before the account's first
  fill. Every stage-2 block rate in FC-002 describes the *engine*.
- **A false confirmation was corrected.** The FC-042 plan cited "the gap filter's blocking of
  NVDA matches production" as validation. Since the filter never ran live, the agreement was
  **coincidence** — it made the engine look better validated than it was.
- **The OCC-substring bug family is at six instances** (FC-041, 043, 045, 048, 052, 054).
  `'P' in symbol` over a full OCC symbol tests the *ticker's* letters; AAPL, SPY and PFE all
  contain a P.
- **Production's covered-call below-basis floor may be entirely non-functional** (FC-050).
  Scanner opps carry `cost_basis_per_share`; `execute_call_sale` reads `stock_cost_basis`, so
  the gate self-disables. And FC-029's cost-basis chain lives in a function production never
  calls — **FC-029's headline fix may never have executed in production.**
- **The spread model is *more* conservative intraday, not less** — the opposite of the
  standing caveat's worry.
