# Release Notes — 2026-05-07

## Summary

Five FCs shipped (FC-023, FC-024, FC-026, FC-027, FC-028) plus one filed (FC-025). All driven by a user-led review of the per-symbol drilldown that started "I see four things wrong on this page." Two of the four were real correctness bugs in dashboard math (FC-023 P&L double-count, FC-024 ACB walk view structurally broken since FC-018), one was an enhancement opportunity (FC-026 Decision Quality macros), one was auto-fixed by another change (Phase Timing — same broken view as ACB walk). ### Bug Fixes

- **Per-symbol Realized P&L card double-counted gross premium** (FC-023, [VsBuyAndHoldCard.tsx](dashboard/frontend/src/components/v2/VsBuyAndHoldCard.tsx) + [fc018_views.sql](docs/bigquery/fc018_views.sql)). Pre-fix: `wheelTotal = realized_pnl + total_premium` — but `realized_pnl` is already net of buyback cost (`premium_total − close_cost` for early-closes, `premium_total` for assignments/expirations), so adding `total_premium` again was a double-count. Same bug mirrored in the SQL view's `wheel_minus_bh` formula. UNH pre-fix: top "Realized P&L" card showed $4,334 (option-only — silently dropped −$1,750 share leg); Wheel-vs-B&H "Wheel" total showed $10,222 (double-count); Δ vs B&H showed +$9,224 (overstated wheel by $7,638). Post-fix: both surfaces show $2,584 with subtitle "option +$4,334 + share −$1,750"; Δ shows +$1,586. View `fc018_vs_buy_and_hold_per_symbol.wheel_minus_bh` rewritten to use canonical `total_realized_pnl`.
- **ACB Walk view structurally broken since FC-018** (FC-024, [fc018_views.sql](docs/bigquery/fc018_views.sql) + [components/v2/AcbWalkChart.tsx](dashboard/frontend/src/components/v2/AcbWalkChart.tsx)). `fc018_acb_timeline_per_symbol` sourced from `trades_with_outcomes`, which is filtered to opening sell_short FILLs only — so OPASN (assignments / called-aways), OPEXP (expirations), OPTRD (share movements), and buy_to_close FILLs **never reached the timeline**. Cross-symbol verification: 7/7 symbols had `rows_w_acb=0`. The yellow ACB line never rendered; reference dots collapsed to `y=0` on the ACB axis (invisible at chart floor) because the dot Y-coord fell back to `acb ?? 0`. Same broken view fed `get_phase_timing()`, which is why observation #4 ("only short_put has values") manifested. Rewrote the view to source from `trades_from_activities` directly via four UNION-ALL blocks (opens / closes / OPASN with QUALIFY-guarded OPTRD pairing / OPEXP). Reference-dot positioning fixed via exported `dotAxisFor()` helper — rides ACB axis when shares are held, premium axis otherwise. UNH cycle 1 verified: assignment Nov 7 → ACB $323.86; call sold Nov 10 → ACB $314.01 (premium credit); called away Nov 15 → ACB NULL.
- **Phase Timing only emitted `short_put`** (auto-fixed by FC-024). Same view bug as ACB walk; the Python state machine never observed an OPASN/OPEXP/buy_to_close event, so it could only enter `short_put`. Post-fix UNH state machine returns the four-phase split: cash 124d / short_put 61d / long_stock 10d / covered 17d.
- **Cycle Table "Cycle P&L" column mislabeled** (FC-027, see Features). Same class of bug as FC-023 at the cycle granularity.
- **`fmtDate` calendar-date off-by-one** (FC-028, [utils/format.ts](dashboard/frontend/src/utils/format.ts)). Pure-date strings like `"2026-04-24"` were parsed as UTC midnight, then converted to ET (UTC−4 EDT) — rolled back to "Apr 23 8pm" and rendered as "Apr 23". Affected Trade Log Expiration column (visible: `UNH260424P00302500` rendered as "Apr 23") and Date column. Fix detects YYYY-MM-DD-shaped inputs and renders directly from year/month/day parts; full ISO 8601 timestamps (`T...Z`) still ET-anchor per FC-022.

## Key Decisions & Rationale

- **One canonical "Realized P&L" number across the page (FC-023 design choice (a)/(a)).** The user offered four ways to fix the discrepancy: (a) switch to `total_realized_pnl` everywhere with breakdown subtitle, (b) keep top card option-only and add a parallel Share P&L card, (c) hot-fix only the frontend, (d) view + frontend together. Chose (a) + (d): both surfaces display the same canonical value; subtitle "option {x} + share {y}" preserves the breakdown; view rewrite ensures other consumers (`SymbolUniverseTable`, `SymbolScorecard`) also benefit. Tradeoff: any consumer reading `wheel_minus_bh` sees a different number post-fix (this is intentional — they were all wrong in the same way, now all right in the same way).
- **OPASN ↔ OPTRD events folded into a single dot, not rendered separately (FC-024).** Alpaca emits paired OPASN+OPTRD on assignment/called-away. Three options considered: (a) one combined dot per pair (cleaner UX), (b) two dots per pair (more data), (c) emit only OPTRD (which has the cash flow) and skip OPASN. Chose (a) — emit one OPASN row with `share_cost_delta` populated from the matching OPTRD's `net_amount`, fall back to `strike × |qty| × 100` if no OPTRD match. The OPTRD itself is filtered out of the events CTE. Result: clean "assigned" and "called_away" dots without double-rendering simultaneous events.
- **Cumulative-since-inception ACB, not cycle-isolated (FC-024 Non-goal).** Wheel-community formula `(share_cost − cum_premium) / shares` keeps `running_share_cost` cumulative across all cycles. After UNH cycle 1's called-away leaves a residual −$1,750 in `running_share_cost`, cycle 2's ACB starts at $30,000 / 100 not $28,250 / 100. This is consistent with the documented formula but means prior-cycle losses carry into the current cycle's ACB. Cycle-isolated ACB is filed as a deferred concern (no FC yet); FC-020 (FIFO pairing) handles a different overlapping-lot scenario.
- **Reference-dot Y-axis selection switches based on shares-held state (FC-024).** Pre-fix dots were always pinned to ACB axis with `y={acb ?? 0}` — dots during cash phases (`acb=null`) collapsed to y=0 on an axis with no data range, rendering invisible. Two fix options: (a) skip dots during cash phases, (b) plot them on the premium axis at `cumulative_net_premium`. Chose (b) — every event remains visible, and the dot rides whichever line is "the" line for that period. Refactored into `dotAxisFor(row)` pure helper exported from the component for testability.
- **"Foregone" label qualified with "(buybacks)" rather than something neutral (FC-026).** Concern: "Foregone" has another reasonable reading — counterfactual profit that *would have* materialized if held to expiry. That interpretation requires option-chain snapshots at decision time (FC-017's territory) and is explicitly out of scope. Qualifier "(buybacks)" + tooltip on hover prevents misreading without renaming the field.
- **Cycle Table column rename followed user's exact request: "Total Premium" + "Cycle P&L" (FC-027).** I'd considered "Net Option P&L" or "Option P&L" as more accurate labels for the existing data (since it IS net of call buybacks during rolls). Chose to match the user's preferred terms because: (a) the data IS gross premium for the put side and net for the call side — "Total Premium" captures the spirit; (b) the user's request was specific; (c) "Option P&L" already means something else on the FC-019 Overview scorecard, would create cross-page inconsistency.
- **FC-028 plan-exempt (single-file utility bug fix).** CLAUDE.md exempts "single-file, isolated bug fixes that don't change behavior contracts." `fmtDate` was always *supposed* to render the literal calendar date for a YYYY-MM-DD input; the implementation was just wrong. Filed FC-028 entry for traceability but skipped the formal plan file. Branch+PR per project policy held; commit message tagged `[no-plan: single-file bug fix]`.
- **PR base trick on dependency chains (lesson learned).** Opened FC-024 with base = FC-023 branch so the diff was minimal during review. After FC-023 squash-merged to main, GitHub auto-closed FC-024 (base branch deleted before retarget). Solution: opened a fresh PR (#30 replacing the auto-closed #28). Lesson for future dependency chains: **retarget the dependent PR's base to main BEFORE the base PR merges**, or use `gh pr merge` with a different sequencing strategy.

## Discoveries

- **AMZN has the same Alpaca paper-engine silent-exercise bug as AMD (FC-021).** Filed as **FC-025**. AMZN $240 put `AMZN260116P00240000` sold 2026-01-12 for $73 premium, expiring 2026-01-16 with AMZN at $239.09 ($0.91 ITM — would auto-exercise). No OPASN/OPTRD ingested. The shares "appeared" silently and were called away on 2026-04-23 at exactly the $240 strike for $24,000. Without the missing assignment leg, AMZN's `share_side_pnl` is inflated by exactly +$24,000 ($20,500 vs the actual −$3,500). Cross-symbol detector query: `SELECT * FROM trades_with_outcomes WHERE outcome='open' AND expiration < CURRENT_DATE()` — returned only this one row at scan time (2026-05-07). FC-025 correction shape mirrors FC-021: synthetic OPASN+OPTRD pair with `synthetic-fc-025-` prefix.
- **The `outcome='open' AND expiration < CURRENT_DATE()` query is the canonical paper-engine-silent-exercise detector.** Two occurrences now (FC-021 AMD, FC-025 AMZN). If a third happens, worth promoting the synthetic-row writer to a reusable `tools/diagnostics/correct_silent_exercise.py` utility.
- **The dashboard reconciles cleanly to raw Alpaca for UNH.** End-to-end walk-through: 60 raw activities pulled from `/v2/account/activities`, manually summed cycle-by-cycle. Top "Realized P&L" card $2,584 ✓, Wheel-vs-B&H Wheel $2,584 ✓, Δ +$1,586 ✓, Total Premium $5,888 ✓ (with put $3,862 / call $2,026 split), Decision Quality Received/Captured/Foregone ✓, Cycle Table 3 rows ✓, ACB Walk yellow line during 3 cycle windows ✓, Phase Timing 4-phase split ✓. The user's "accurate numbers are paramount for reporting" goal is met for UNH and by symmetry for the other clean symbols.
- **Closed-cycle realized option P&L equals `cumulative_net_premium` exactly when no positions are open.** Useful invariant for spot-checks: at end of any phase where `open_count = 0`, the dashboard's `realized_pnl` (sum of per-row option-leg P&L) should equal the ACB chart's blue-dashed-line endpoint (cumulative net premium). UNH end-of-period: both = $4,334.
- **Recharts `<Legend>` legend in jsdom doesn't expose dot fill colors via `<circle>` SVG attributes the way I expected.** First attempt at FC-024 dot-axis tests asserted `circle.fill` matched specific hex values; tests failed because Recharts' rendering pipeline doesn't put fills directly on SVG circles in the test environment. Pivoted to a pure-helper approach: extracted `dotAxisFor()` from the component, exported it, and unit-tested the function directly. Faster, more reliable, and not coupled to Recharts internals.
