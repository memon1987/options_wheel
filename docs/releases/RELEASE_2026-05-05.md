### Bug Fixes

- **Empty per-symbol cycle table** (PR #15, `dc843e1`): `cycles` API filtered by underlying but the frontend wasn't passing the `underlying` parameter — root cause was a missing query-string append in the symbol drilldown's `useApi` call.
- **Cycle premium under-counted rolled calls** (PR #16, `af3f735`): the cycle aggregation only counted the first call leg; rolls were dropped. Fix changed the aggregation to sum all calls within the cycle window (`calls_in_cycle`, `cycle_call_gross_premium`, `cycle_call_net_realized`).
- **Gross-vs-net premium mislabeling** (PR #17, `f3073fa`): scorecard column header said "Net P&L" but the underlying value was gross-of-buyback premium. Renamed to "Option P&L" and reworked the SQL to subtract roll buybacks. This is the audit that surfaced the $26k vs $20k reconciliation gap and triggered FC-019.
- **Total Return diverged from account growth** (PR #18, `4862159`): Total Return previously summed realized P&L across cycles, which double-counted assignment economics. Replaced with `NLV − sum(JNLC deposits)`. Plus the FC-019 ingest of share-side OPTRD cash flow into per-symbol scorecard.
- **Per-symbol Total P&L did not reconcile to headline** (PR #19, `78acf92`): root cause — cycle pairing math doesn't account for OPTRD (assignment / called-away) cash flow on the share side. Added `share_side_pnl` from raw OPTRD activity log and `total_realized_pnl = realized_pnl + share_side_pnl` to the scorecard. After fix: sum of per-symbol Total P&L = $21,808 vs account growth ~$20,080, leaving a ~$1,728 gap concentrated entirely on the AMD anomaly (filed as FC-020).

## Key Decisions & Rationale

- **One PR per logical step, even within a single FC.** FC-018 shipped as 9 PRs (skeleton → backend → pages → 4 review fixes → Trade Log → gap-closing → cutover → cleanup). The bias is toward small, atomic, reviewable PRs over a single mega-PR. Each PR independently rollback-able. CLAUDE.md "one PR per FC" rule is loosened in practice when the FC is L-sized.
- **Strangler over big-bang cutover.** PR A added `/v2/*` routes alongside the legacy frontend; users could compare side-by-side. PR F redirected legacy paths to `/v2/*` (cutover). PR G dropped the `/v2/` prefix and added bookmark-compat redirects in the opposite direction. Eliminates the "live for 5 minutes, broken everything" risk.
- **Archive over delete on cutover.** Legacy frontend lives under `dashboard/frontend.archive/` with a revert README. Cost: ~6 dead files in the repo for ~2 weeks. Benefit: cheap rollback during the bake window and zero risk of "wait, what did the old version do for X?" rediscovery via `git log` archeology. Recommend deletion target ~2026-05-19.
- **FC-019 branched off FC-018 mid-flight.** When the gross-vs-net premium audit surfaced a $26k vs $20k mismatch, options were: (a) patch the scorecard label and call it shipped, or (b) do the full reconciliation. Chose (b) because half-fixing P&L visibility is worse than not fixing it — users would see "Net P&L" and trust it. Cost: an extra 3 PRs (#17, #18, #19) and ~2 days. Benefit: the dashboard actually reconciles to the brokerage account.
- **FC-020 (FIFO cycle pairing) parked, not solved.** The cleaner fix for the AMD anomaly is FIFO pairing of share lots within `wheel_cycles_from_activities`. Considered shipping it inside FC-018 but: (a) AMD's anomaly is upstream Alpaca data (3 OPTRD buys + 2 OPTRD sells netting to a missing 100 shares), not a pairing-algorithm bug; (b) FIFO over SQL UDFs is brittle; recommended a Python-side walk; (c) FC-018 had already grown to 9 PRs. Filed as FC-020 with plan in Draft.
- **Total Return = NLV − sum(deposits) over realized-P&L sum.** Realized-P&L summing across cycles double-counts assignment economics (premium recorded once at put-side, share economics recorded again at assignment). NLV − deposits is the brokerage truth. Trade-off: NLV moves daily with unrealized P&L; for a "wheel-the-week" trader this is fine because unrealized is small relative to realized.
- **Stock-history ingest only when dashboard needs it.** The scheduler runs `0 17 * * 1-5` (5pm ET, weekdays) — once per trading day after close. Idempotent on `(date, symbol)`. The 365-day backfill ran on first invocation; subsequent runs add ~7 rows/day (one per symbol). Considered backfilling 2 years (730 days) but 365 is enough for first-year vs-B&H math and halves storage.
- **VSCode dashboard-folder-red diagnosis: missing venv deps + sibling-import resolution.** Initial guess was gitignore tinting (correctly identified `dashboard/frontend/dist/` and `node_modules/` as ignored), but the actual cause was Pylance flagging `from fastapi import FastAPI` and `from routers import live` across the entire backend. Fix: install the three missing pip packages without forcing strict version pins (would have downgraded shared deps), plus `.vscode/settings.json` setting `python.analysis.extraPaths` to include `dashboard/backend`.

## Discoveries

- **AMD anomaly is real and Alpaca-side.** AMD's OPTRD activity log shows 3 share-buys (assignments) and 2 share-sells (called-aways) — should leave 100 shares. Alpaca reports 0 shares. Rather than ours to fix, this is a brokerage data-quality issue. The dashboard surfaces it as a −$24,250 share P&L line that masks an otherwise-positive AMD wheel. FC-020 will recategorize it as `unaccounted_shares_loss` rather than burying it in share P&L.
- **5 of 7 traded symbols beat buy-and-hold over the period.** AMZN, NVDA, UNH, IWM, AMD beat; GOOGL and AAPL lag. AAPL is essentially zero (1 trade, 0 cycles, $73 — single open put). This is the first time we have per-symbol vs-B&H attribution; previously the dashboard had only headline-level numbers.
- **Cloud Build auto-triggers on every main commit, even docs-only.** Pushing the FC-018 bookkeeping commit (`5da09f8`, docs only) kicked off a strategy-service rebuild. Harmless but wasteful. If this becomes annoying, add a path-filter to the Cloud Build trigger.
- **`pydantic` 2.5.3 (dashboard) vs 2.11.7 (bot) version mismatch.** The dashboard's `requirements.txt` pins old versions; the bot's root `requirements.txt` doesn't pin them. Both Cloud Run images install their own — no production conflict — but local dev hits a divergence if you `pip install -r dashboard/backend/requirements.txt` into a venv shared with the bot. Worked around by installing only the missing-from-bot pieces (`fastapi`, `uvicorn`, `httpx`).
- **Cloud Run dashboard service is healthy at `00145-ley`; strategy service deploy queue runs ~7 min behind merges.** Two builds were in-flight at session-end (merge of PR #25 and the docs commit). Neither gates the dashboard.
