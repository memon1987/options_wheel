## Context

`WheelEngine.run_strategy_cycle()` and everything beneath it — `_find_new_opportunities`, `_manage_existing_positions`, `CallSeller.evaluate_covered_call_opportunity`, `PutSeller.find_put_opportunity` — have not been called by production since 2025-10-03 (`842dcce` removed them from `/run`, three days before the live account's first fill). Production trades exclusively via `/scan` → `OptionsScanner` → GCS opportunity blob → `/run` → `ExecutionEngine.rank/select_batch/execute_batch` → `PutSeller.execute_put_sale` / `CallSeller.execute_call_sale`.

The backtest simulator (`src/backtesting/engine/simulator.py`) replays the dead half for opportunity *generation*: it calls `run_strategy_cycle()` and hands the resulting actions to `ExecutionEngine` (the execute half was already repointed by FC-048). So every backtest measures a strategy with:

- a **drawdown pause** production does not have (FC-065 OQ-3 decided it never will),
- **gap filtering** (stages 2 and 4) production does not run (FC-049),
- **wheel-state phase gating** (stage 5) resting on a fictional state layer (`STATE_STORAGE_BUCKET` never set),
- **single-candidate selection** (first suitable contract per symbol) instead of production's top-3-per-symbol → attractiveness-ranked → two-pool batch selection (FC-038),
- **per-cycle caps** (`max_stocks_evaluated_per_cycle`, `max_new_positions_per_cycle`, `_can_open_new_positions`) production does not enforce anywhere,

and *without* the committed-share ledger and floor/cross-check semantics production does have. Ten months of remediations landed on the unused half (FC-029 R2/R3, FC-048's origin, FC-050's root cause, FC-065's finding). FC-065's three phases replaced everything the dead path uniquely guarded; this FC deletes it and repoints the simulator so the next backtest measures the strategy that trades.

**Base assumption (sequencing):** this plan is written against, and must be built on, `main` **after both** `fc-065/phase-2-roller-floor` (roller floor via shared resolver + the roller's replay-BQ gate) **and** `fc-065/phase-4-decision-record` (decision records, `run_id`, `UncoveredDaysResolver`, un-zeroed `call_sale_executed` telemetry) **merge**. Line references below are against today's `main` (post-P1, `a66e30e`) and drift by a few lines after P2/P4; symbol names are the contract. If P4 is deferred, the `UncoveredDaysResolver` threading item (§Replay isolation, row 2) drops out and the rest of the plan stands — noted so a P4 slip does not block this FC.

Operator decisions carried in as **binding constraints** (do not relitigate at build time):

1. **The pause is not ported** (FC-065 OQ-3). The pause tests and the `covered_call_drawdown_pause` taxonomy entry are **deleted with the path**, not migrated.
2. **The `call_drawdown_pause_threshold` knob is NOT deleted here.** FC-069 item 9 owns the knob, its `/config` endpoint field, and the dashboard exposure. FC-068 deletes only its last consumer and leaves the knob deliberately orphaned (see §FC-069 boundary).
3. **Engine-path guard tests migrate where they pin behavior the live path keeps** (the floor family); FC-065 P1 already rewrote the R2-chain subset against the inverted resolver.
4. **Affected backtest verdicts are re-run; pre/post numbers are non-comparable** (FC-048 precedent).

## Goals

- **One candidate-generation path.** The simulator replays `OptionsScanner.scan_for_put_opportunities()` + `scan_for_call_opportunities()` → `filter → rank → select_batch → execute_batch` — the exact production pipeline — instead of `run_strategy_cycle()`.
- **Delete every function on the dead path**, its orphaned tests, and the two config knobs whose only consumers die here.
- **Close the interim floor gap** recorded in `docs/plans/fc-065.md` Phase 1 ("the backtest floor sits one put premium above production's... FC-068 closes it"): the backtest broker's assignment basis becomes premium-netted, matching Alpaca's `avg_entry_price` semantics.
- **Keep every replay hermetic**: no BigQuery reads, no GCS writes, no production analytics rows, from any component the repoint newly pulls into the replay (scanner's resolver, `UncoveredDaysResolver`, decision records).
- **Zero behavior change on the production path.** `/scan`, `/run`, `/monitor`, `/roll` behave identically before and after; this PR is dead-code deletion plus backtest-only changes plus additive constructor parameters with production-preserving defaults.

## Non-goals

- Reviving or deleting any control on FC-069's inventory (position caps, earnings gate, gap detector, `WheelStateManager` shrink, `min_hold_hours`, `rolling.*` knobs, `docs/CLAUDE.md` architecture claims). See §FC-069 boundary.
- Fixing the scanner's put-side substring bug (`_has_existing_position`, `symbol in position['symbol']` — FC-069 item 12). The replay will now faithfully reproduce it; that is the point of a replay.
- The roller's revival (FC-066) or its eligibility/quote-key fixes.
- Modeling the monitor cycle (profit-taking / stop-loss churn) in the backtest — unmodeled today, unmodeled after; recorded in `docs/BACKTEST_ENGINE.md`.
- Backfilling or editing `backtest_runs` rows. Pre-FC-068 rows are annotated by provenance, never mutated.

### 4. The repoint — `src/backtesting/engine/simulator.py`

Replace the generation half of the day loop (today at :322–334 engine construction, :372–373 cycle + execute, :551–583 `_execute_opportunities`) with the production pipeline:

```python
# Construction (once per run):
engine = WheelEngine(config, alpaca_client=client,
                     wheel_state=WheelStateManager(storage_bucket=None),
                     allow_bigquery_cost_basis=False,        # roller gate (P2)
                     earnings_calendar=self.earnings_calendar)  # roller only, post-slim
scanner = OptionsScanner(client, market_data, self.config, allow_bigquery=False)  # NEW param, §Replay isolation
exec_engine = ExecutionEngine(client, self.config, logger, trade_journal=NoOpTradeJournal())
put_seller = PutSeller(client, market_data, self.config)
call_seller = CallSeller(client, market_data, self.config)   # no wheel_state — exactly as /run builds it

# Day loop (replaces run_strategy_cycle + _execute_opportunities):
engine.reconcile_positions()                                  # unchanged pre-trade housekeeping
puts = scanner.scan_for_put_opportunities()                   # default max_results=10, as /scan calls it
calls = scanner.scan_for_call_opportunities()                 # default 10; mints its own run_id
opportunities = puts + calls
opportunities, _ = exec_engine.filter_failed_opportunities(opportunities)
opportunities, _ = exec_engine.filter_duplicate_opportunities(opportunities, client.get_positions())
# then the existing snapshot → rank_opportunities → select_batch → execute_batch, unchanged

    engine.run_rolling_cycle()                                # kept — see decision below
```

Specifics, each a deliberate decision:

- **`MarketDataManager` is constructed once in the simulator** and shared by scanner and sellers (WheelEngine keeps its own for the roller). Same adapter client throughout — the single injection seam is unchanged.
- **Scanner default `max_results` values are used**, because `/scan` uses them (`cloud_run_server.py:168,175` pass no args). Diverging would measure a different strategy.
- **`filter_failed_opportunities` is now CALLED, matching `/run`** — and `clear_failed_symbols()` is called once at `Simulator.run()` start. Two corrections in one: (a) the current simulator skips the filter with a docstring claiming it "reads the GCS opportunity store," which is false — it reads the module-global `_failed_symbols` set (report: pre-existing doc error); (b) that module-global currently leaks non-retryable failures **across the 14 sequential per-symbol runs of a screen** in one process. Clearing per run makes replays hermetic; production is unaffected (its set intentionally persists intra-day and clears on cold start).
- **The opportunity blob is not simulated.** `/scan` and `/run` are ~15 minutes apart in production with fresher quotes at execution; the replay scans and executes on the same snapshot. That is today's behavior too — unchanged, and now stated in `BACKTEST_ENGINE.md`.
- **`reconcile_positions()` stays in the loop** — production runs it before every `/run`, and in the replay it is what detects assignments/expirations against the adapter. Its `wheel_cycles` analytics writes go to the NoOp writer (already swapped).
- **The Friday `run_rolling_cycle()` call is KEPT.** Decision, with rationale: the roller *is* production code — the Friday `/roll` scheduler job invokes it weekly (that it has never executed a roll, FC-066, is a property of the code the replay should faithfully reproduce, not a reason to un-model it). P2 gave it the replay BigQuery gate precisely so it could keep running inside replays, and FC-066's eventual fix will want a replay that already exercises the path. Rejected alternative: remove the call because `rolls_executed=0` always — that deletes the measurement seat for FC-066's fix and makes the replay diverge from the production week for no cost saving.
- **`_flush_run_decisions` (P4's `/run`-stage decision record) is NOT mirrored** in the replay: it is server-layer telemetry in `deploy/cloud_run_server.py`, all of its output goes to analytics (NoOp'd in replay), and the replay's measurement comes from the broker ledger + rejection tally. The scan-stage records fire inside `scan_for_call_opportunities` regardless and are absorbed by the NoOp writer (verified: `DecisionRecorder.flush` → `get_analytics_writer()` → the swapped singleton; `NoOpAnalyticsWriter` answers any method name by design).
- **Warm-up bars are retained** but the comment at :152–159 is rewritten: the GapDetector rationale dies with the gap stages; the surviving reason is `market_data.get_stock_metrics` / `filter_suitable_stocks` lookbacks (volatility metrics need history on day one).
- **Scanner timestamps switch from `datetime.now()` to `clock.now()`** (`options_scanner.py:264,330,454` and the `scan_all_opportunities` envelope). Behavior-neutral in production (`clock.now()` is wall time when unfrozen); inside a replay the frozen clock makes `scan_timestamp` honest. Report: found during planning — the scanner is the only strategy-path module still stamping wall time.

### 7. Close the floor gap — premium-netted assignment basis in `BacktestBroker`

**Today:** `broker._assign_put` (`broker.py:401–413`) books the lot at `pos.strike`; the adapter derives `avg_entry_price` from lot basis (`alpaca_adapter.py:173,188`); post-P1 the scanner floor = adapter `avg_entry_price` ⇒ **backtest floor = strike**. Production's floor is Alpaca's `avg_entry_price` = strike − the assigning put's premium (verified to the penny on all four live lots, FC-065 P1). The backtest floor sits one put premium **above** production's — accepted in writing in `docs/plans/fc-065.md` Phase 1 with "FC-068 closes it."

**Decision: close it.** `_assign_put` books the lot at `pos.strike - pos.entry_price` (the short put's fill premium per share, which the position already carries), floored at `> 0` as a sanity guard. Multi-lot weighting falls out of the existing lot list + `average_cost_basis`, exactly matching Alpaca's weighted-average semantics.

**Why close rather than accept-and-document:** IWM — a $1-strike-grid underlying — is in the six-symbol effective universe. On a $1 grid, a one-premium floor offset (~$1–1.50) moves the qualifying strike set by a full rung on a normal assignment (the exact arithmetic that drove FC-065 OQ-1), so "accept" means every IWM backtest gates calls one strike tighter than production would. On $2.50-grid names the gap is currently invisible, but the plan should not depend on the universe staying coarse-grained. The fix is one line plus tests.

**Consequences, stated:** the equity curve is mark-to-market and does not read lot basis — unchanged. What changes: the scanner floor in replays (intended), the `cost_basis` detail on the broker's `put_assignment` ledger record (update the `detail` dict to carry both `strike` and `basis` so reports stay explicit), and any report field echoing basis. `test_no_call_is_sold_below_cost_basis` re-asserts against the netted basis. One deliberate residual: the broker's `entry_price` is the *haircut* fill premium, so the netting reflects the replay's own fill model rather than a hypothetical mid fill — consistent with how the replay's cash ledger already works.

### 8. What the measurement now means — expected consequences of batch selection

For reviewers of the *next* backtest, the replay's semantics change as follows (each traceable to a production mechanism, none to backtest scaffolding):

- **Put leg:** the engine emitted ≤1 put candidate per symbol per cycle behind gap + wheel-state + per-cycle caps. The scanner emits top-3 per suitable symbol across the universe; `select_batch` takes puts by ROI, one per underlying, until buying power is exhausted, **with no global position cap** — production's actual (capless — FC-069 item 1) behavior. Expect more concurrent short puts and faster capital deployment; block-rate attribution shifts from "gap filter / wheel state" to "insufficient buying power / sizing".
- **Call leg:** the pause is gone — a symbol 5–15% underwater whose chain still clears the floor+delta+premium bands now writes calls in replays, as production does. Selection moves from "first suitable strike" (`suitable[0]`) to "top-3 by chain order, ranked by `attractiveness_score`, best available shares win" — the measured strike mix will shift, which stales the 55.2% call-leg strike-reproduction figure (§10). Committed-share accounting (FC-038 ledger) now applies: a covered position cannot be double-covered; expect measured call frequency to *drop* on multi-contract positions relative to the old path's fictional-state gating (which could re-emit while a call was pending) and to *rise* on drawdown symbols the pause used to silence. Net direction is symbol-dependent; that is precisely why verdicts must be re-run, not extrapolated.
- **Gap filter:** stages 2 and 4 no longer run anywhere. Symbols the engine's gap filter excluded in elevated-vol regimes (AMD from 2025-01-13 in the FC-002 study) now trade in replays — as they always did in production.
- **Unchanged limitations, restated in the doc:** monitor-cycle churn (profit-taking closed 52% of real call positions early) is still unmodeled; scan-time == execution-time in replays; premium fills carry the same haircut model.

## Risks & mitigations

- **Risk: the repoint silently changes production `/scan` behavior via the new scanner param.** Mitigation: default `allow_bigquery=True`; test 3 pins the default; the PR diff to `cloud_run_server.py` must be empty except P4-owned lines (reviewer checklist item).
- **Risk: replays read production BigQuery through a missed chokepoint.** Mitigation: the §6 table is exhaustive by construction (every import on the scan→select→execute path audited); conftest class-level patches backstop tests; gate tests 1–2 prove the production-code gates fire without the backstop.
- **Risk: premium-netted basis breaks a report or metric that assumed basis == strike.** Mitigation: ledger `detail` carries both numbers; full metrics/report test suite must pass; grep for `average_cost_basis` consumers during build (`alpaca_adapter` is the only strategy-path reader today).
- **Risk: deleting `find_put_opportunity`/`evaluate_*` orphans a behavior only their tests pinned.** Mitigation: the §9 mapping table is a build-time checklist — every row verified against the named live-path test before the deletion commit; unverifiable rows become migrations, per binding constraint 3.
- **Risk: the golden replay passes vacuously (e.g., zero trades) after the repoint.** Mitigation: `TestTheCallLegActuallyRuns` asserts positive counts and full-cycle ordering; `test_empty_window_refuses...` already guards the zero-trade report; test 7 asserts the dead vocabulary is gone, so a half-repoint cannot pass.
- **Risk: verdict flips get read as strategy changes.** Mitigation: `engine_version` stamp + `BACKTEST_ENGINE.md` boundary + the PR memo listing per-symbol pre/post verdicts side by side, labeled non-comparable.
