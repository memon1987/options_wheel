## Context

FC-065 was filed as "port FC-029's drawdown pause to the production path." Three investigations (mechanism inventory, floor economics, lifecycle coherence) show that framing is too narrow: the pause is one symptom of a structural condition, and patching it alone would add a **fifth** guard to a layer that already has four cost-basis floors on two code paths.

**What the investigations established:**

1. **Production runs a stateless wheel.** Phase is emergent from Alpaca positions + BigQuery history. The codebase maintains a parallel *stateful* wheel (`WheelStateManager`, phases, premium accumulators, roll counts) that is rebuilt per request and discarded — `STATE_STORAGE_BUCKET` has never been set. Nearly every defect in the FC-029/038/045/048/050/062/065/066 family is a control installed on the fictional half.
2. **The drawdown pause has a silent substitute.** On the live path, an underwater position's above-basis strikes fall below 0.15 delta, so candidates die as `delta_out_of_range` and the symbol quietly yields nothing. Same outcome as a pause, with no event saying "paused," no threshold to tune, and no escalation hook. Verified: every NVDA scan since 07-30 ends `stage_8_complete_not_found` with `rejected_delta_out_of_range: 0` — the whole band sits below the floor.
3. **The floor is currently the wrong value, and the data says so.** FC-050 (shipped 07-30) made the floor the **raw assigning-put strike** (F1). Reconstructing all 16 share lots and 88 covered-call writes from `trades_from_activities` shows the **broker premium-adjusted basis** (F2 = put strike − put premium) is strictly better: it catches every write F1 usefully caught — including all three called-away disasters totalling **−$9,000** — while additionally permitting 4 writes F1 wrongly blocked, all of which closed profitably (**+$279**). F2 is also the loosest floor with an analytic guarantee: assignment at K ≥ (strike − put premium) makes the cycle net ≥ 0 before any call premium. **F1 blocks trades that are provably non-losing.**
4. **Four live defects nobody had catalogued**: every production `call_sale_executed` logs `shares_covered=0, stock_cost_basis=0, total_return_if_called=0` (the *fourth* instance of the untyped-shape root cause); `wheel_cycles` holds 36/30/6 duplicate zero-gain rows per assignment; the floor's BigQuery source is age-bounded to 90 days so it **silently reverts** to Alpaca basis (AMZN/GOOGL age out 2026-09-04, NVDA 09-07, AAPL 09-11) with no event; and call limit pricing (`mid × 0.95`) never received the put side's spread-aware improvement.
5. **The backtest measures a strategy nobody trades.** The simulator replays `run_strategy_cycle` — the dead engine path — which has a drawdown pause, phase gating, single-candidate selection, and no committed-share accounting. Production has none of those and has extra ones the backtest lacks.

**The through-line:** where the Symmetry Principle could be enforced by code proximity it held; where it required carrying a change across files it broke every time. That argues for structural enforcement, not more review discipline.

## Goals

- **One floor value.** A single, economically justified definition (F2), computed identically by every source, so a disagreement between sources is a real anomaly rather than expected noise.
- **One floor implementation.** Every order-placing path resolves the floor through `CostBasisResolver` and passes the same gate. No path fails open.
- **Regime protection on the path that trades**, as an explicit, tunable, observable decision rather than an emergent side effect of the delta band.
- **A legible decision record**: for any symbol on any cycle, a durable answer to "did we sell a call, and if not, why not."
- **One candidate-generation path**, so what the backtest measures is what production does.

## Non-goals

- Changing the delta band, premium floor, DTE target, or any filter threshold (FC-029/FC-034 territory).
- Permitting below-floor writes on underwater positions — that is a real policy question with real money attached (≈ **$130/week/lot** foregone on NVDA today), but it is **FC-033's** scope and it now has the numbers it was waiting for. Explicitly out of scope here.
- Wheel-state persistence (FC-039). This plan assumes it stays dead and derives from durable sources instead.
- The roller's revival (FC-066). Phase 2 fixes the roller's *floor* (satisfying FC-062's floor half); reviving the roller remains separate.
- Backfilling or correcting historical data (`wheel_cycles`, `trades` labels — FC-067, and the spin-off below).

## Proposed approach

### Phase 1 — One floor value: adopt F2

Change the BigQuery source in `CostBasisResolver._lookup_last_opasn_put_strike` to return **assigning put strike − assigning put premium**. The premium is already present in `trades_from_activities` (the sell-to-open fill on the assigning contract), so this is a query change plus arithmetic, not new plumbing.

**Why this specific definition** (full analysis in the investigation record; summary of the alternatives considered and rejected):

| Definition | Blocks | Disasters caught | Naive net | Verdict |
|---|---|---|---|---|
| F1 raw strike (today) | 15 | 3 of 3 | +$3,426 | Blocks 4 provably-non-losing trades |
| **F2 broker basis (recommended)** | 11 | 3 of 3 | **+$3,705** | Loosest floor with a no-guaranteed-loss guarantee |
| F3 net-of-cycle (ACB-style) | 13 | 3 of 3 (+1 false block) | +$2,525 | **Actively dangerous** — see below |
| F4 premium-offset | 10 | 3 of 3 | +$3,901 | Indistinguishable from F2 (n=1 trade, $196) |

**F3 is rejected on evidence, not taste.** It is path-dependent and ratchets: after AMD's losing buyback, cycle cash went negative and F3 rose *above* F1, blocking the recovery trade that exited the lot at +$860; and in the AMZN chain F3 fell 246.38 → 224.53 as roll-down premium accrued, meaning collected premium becomes license to lock in ever-lower strikes. A few more weeks and F3 would have *permitted* the −$3,500 disaster write. Net-of-cycle basis is the right **scorekeeping** number (that is what the FC-024 ACB views are for) and the wrong **guard**. Extreme case: NVDA's lifetime ACB is $156.79 against a $220 lot.

**F4 is rejected on parsimony**, not on being wrong — it differs from F2 by a single historical trade. F2 wins on simplicity and on not letting crash-inflated IV buy lower strikes.

**A property worth having:** Alpaca's reported `cost_basis` **is** F2 (verified against actual put fills on all four open lots — the FC-050 `basis_delta` telemetry of +1.30 to +1.66 is exactly the put premium). So after this change the BigQuery and Alpaca sources compute the *same quantity* and should agree to the cent. Divergence becomes a genuine signal — which is precisely what FC-064's mixed-lot hazard needs, and it dissolves the "expected divergence" noise that would otherwise mask it.

Note this partially revises FC-050, shipped yesterday. FC-050's achievement was making a dead guard run; it inherited F1 from FC-029's chain without the value ever being chosen on evidence. This is the choosing.

### Phase 2 — One floor implementation

- Route `CallRoller`'s floor (`call_roller.py:127-132`) through `CostBasisResolver` and make its zero case **fail closed** — today it degrades to `min_strike = current_strike + 0.01`, which is no basis protection at all, on the one path that places orders without passing `execute_call_sale`. This satisfies the floor half of **FC-062**; routing `execute_roll` through the shared gate remains FC-062's.
- Reconcile the equality semantics: gates allow `strike == floor`, but the scanner's `assignment_above_cost_basis` flag uses strict `>`, so GOOGL's at-floor 370C was flagged `False` and sold anyway. Pick one (recommend: at-floor allowed, flag matches) so the flag stops reading as a warning that gates nothing.
- Make the **90-day cliff** explicit: when the OPASN lookback ages out and the floor source flips, emit an event. Recommend extending the lookback to cover the holding period (the OPASN row does not expire) rather than silently changing semantics on lots held past day 90 — which, by construction, are the long-underwater ones where the floor does the most work.

### Phase 3 — Regime protection on the live path (the original FC-065)

Port FC-029's drawdown pause and defer-on-bad-quote to the scanner path, reusing `CostBasisResolver` and the **existing event names** (`covered_call_drawdown_pause`, `covered_call_quote_missing`) so the backtest rejection taxonomy (`src/backtesting/engine/rejections.py:44`) and any dashboard consumer keep working.

Design decision: implement as a **scanner-side skip**, not a selection-side drop. The pause is a per-symbol regime judgment, not a per-contract one, and skipping at scan keeps the opportunity blob an accurate record of what was considered tradeable. (FC-038's drop-reason model is right for per-contract decisions; this is not one.)

Note the threshold interacts with Phase 1: the floor moves down by one put premium, so re-examine whether 5% is still the right pause threshold. Non-blocking — ship 5% and tune with data.

### Phase 4 — Make the decision legible

- **Fix the zeroed telemetry.** `call_sale_executed` (`call_seller.py:436-438`) reads wheel-engine-only keys; use the same shape-tolerant accessor FC-050 introduced. This is small, and it is the reason FC-029's standing production-validation item is currently unsatisfiable.
- **Emit one decision record per held symbol per cycle** with a closed outcome enum: `sold | no_candidates{reason counts} | dropped{reason} | blocked{floor|unresolved} | paused{drawdown} | not_eligible{<100 shares}`. FC-038's drop-reason enum already proves the pattern works.
- **Make it durable.** Structured events currently live only in Cloud Logging's 30-day window because the BigQuery sink died 2025-11-22 (FC-046), so *a question about last month's decision is already unanswerable today*. Recommend writing the decision record via `analytics_writer` to a dedicated table rather than depending on the sink repair — it fits the codebase's post-sink direction and does not inherit the repeated-field schema collision.

### Phase 5 — One path

Delete the dead engine path (`evaluate_covered_call_opportunity`, `_calculate_call_position`, `wheel_engine._find_new_opportunities` / `_manage_existing_positions`) and repoint the backtest simulator to replay `scan → select → execute`.

**Sequencing is load-bearing: port (Phase 3) before delete.** Deleting first would remove the only implementation of the pause.

**Why delete rather than merge:** FC-050's "extract a shared module, both paths delegate" is right for a single guard but preserves two producers indefinitely as a whole-path strategy. Every incident in this family came from remediating the unused half. **Why delete rather than revive the engine path:** production has voted for ten months; the scan/store/run split is what gives the system its auditable decision record and its Cloud Run cadence fit, and reviving would re-couple candidate generation to a state machine that persistence has never backed.

**Honest cost:** the backtest rework is the real bill. Re-pointing the simulator changes what every future backtest measures, and prior verdicts become non-comparable — the same problem FC-048 hit. Budget a re-run of affected verdicts. The 27 FC-029 tests and the FC-048 golden replay exercise the engine path and must be **migrated, not deleted** — they encode the guards being ported.

## Risks & mitigations

- **Risk: Phase 1 loosens a guard one day after tightening it.** Mitigation: the loosening is exactly one put premium (0.4–0.6%), every historical disaster is still caught, and the analytic no-guaranteed-loss property holds. Ship Phase 1 with a query that lists which currently-available strikes newly qualify, and eyeball it before deploy.
- **Risk: porting the pause starves symbols that currently trade.** Mitigation: the pause fires at 5% underwater; today only NVDA (9.5%) and GOOGL (4.3%) are near it, and NVDA already yields zero candidates. Expected behavior change is ~zero contracts, ~one new event — verify in the first two cycles.
- **Risk: Phase 5 breaks the backtest.** Mitigation: it *changes* the backtest by design. Treat the re-validation as part of the phase, per FC-048's precedent, and do not compare across the boundary.
- **Risk: scope.** Five phases is a lot. Mitigation: each is independently shippable and independently valuable; Phases 1–2 are the money path and can ship alone if the rest is deferred.
