## Context

The dashboard's *data layer* is sound since FC-019 (JNLC/OPTRD reconciliation) — but the *metric layer* on top of it has drifted. A full audit (`docs/investigations/dashboard-metrics-audit-2026-07-07.md`) traced every displayed metric to its computation and found misleading stats plus large bot-observability gaps. External research (CBOE PUT-index methodology, GIPS TWR/XIRR standards, Bailey & López de Prado on small-sample risk stats, wheel-community cost-basis conventions) sets the target: **fewer metrics, each correct, each auditable against the broker statement.**

An adversarial PM/quant review of the first draft (`docs/investigations/fc-031-adversarial-review-2026-07-07.md`) found 7 blockers — most importantly that the draft reused FC-019's *cash-ledger* columns as if they were *disposal-based realized P&L*, which would have double-subtracted the cost of held shares (~$24k error on AMD alone). This revision incorporates every blocker and the strongly-recommended items; the disposition table is at the end.

**The accounting convention (one, everywhere):** FC-019's `total_realized_pnl` is a **net cash P&L** — option premiums netted with buybacks, plus *all* OPTRD share cash including the acquisition cost of shares still held. Therefore:

```
Per-symbol MTM P&L  = net cash P&L  +  market value of held shares  (+ open option marks where available)
Account check       : Σ MTM P&L + open-option premium float + fees  ≈  NLV − deposits
```

Cost basis appears only as (a) **open-lot basis** from a FIFO walk over OPTRD events (display + breakeven distance) and (b) **ACB / effective breakeven** (decision metric). Neither is ever summed into P&L.

Headline defects being fixed (audit refs): asymmetric vs-B&H (realized-only wheel vs MTM benchmark, capital efficiency ignored), ACB-based Unrealized double-count and missing cost basis for long positions, range-dependent single-deposit CAGR, gross premium presented as income, dead `win_rate`/`return_30d` fields, fake freshness stamp, ActionPanel %-math defects, and a Bot Health page that shows raw tables instead of health (no funnel, no anomaly flags, no run SLO, no drawdown-pause visibility, no automated reconciliation).

Note: strategy-review-2026-05-07 §5 speculatively used FC-030/031 numbers for other work; `docs/FUTURE_CONSIDERATIONS.md` is the ledger and wins (FC-030 = drawdown-pause observability, absorbed here; FC-031 = this plan).

## Goals

- **One accounting convention everywhere** (net cash P&L + market value of holdings), reconciling to the broker statement by construction, with drift surfaced automatically.
- **Headline tiles a PM signs off on:** NLV · **Total P&L** (= NLV − deposits, with realized-cash vs open-value split) · **Max drawdown** (% close-to-close and flow-adjusted $) · XIRR/TWR as labeled sub-lines (single-deposit caveat stated). CAGR tile retired *as a tile*.
- **Honest benchmarking:** indexed TWR curve vs same-capital SPY (price-only, dividend + idle-cash-yield bias quantified in caption); per-symbol B&H made symmetric (wheel side MTM) and labeled a perfect-foresight reference; capital-normalized Σ/Σ per-$-day comparison.
- **Hold-time-aware trade metrics:** cycle table gains `$/day per $1k collateral` (per-row only; aggregates only as Σ P&L / Σ collateral-days); **wheel-cycle** and **unassigned-put** stats reported separately (never blended into one "win rate"), with open campaigns shown beside closed stats and an FC-029 before/after regime split.
- **Bot execution health:** decision funnel (stages 1–9 → orders → fills), gate anomaly flags on an *independent* SPY-bar trading calendar, run-reliability rate, drawdown-pause tracker keyed to assignment strikes and live share counts (absorbs FC-030's dashboard half), ingest freshness, and a falsifiable reconciliation check.
- Metric discipline: every metric has a definition tooltip; the banned list (audit §5) does not ship.

## Non-goals

- **No Sharpe/Sortino/beta/alpha tiles** (small-sample noise for skewed short-vol returns; revisit ≥12 months).
- **No counterfactual decision quality** — FC-017.
- **No full FIFO cycle re-pairing** — FC-020 proper. This plan ships only the *open-lot* FIFO subset (basis of currently-held shares) and **excludes overlapping-lot symbols from cycle aggregates with disclosure** rather than aggregating known-wrong rows.
- **No slippage/fill-quality analytics** (decision-time mids not persisted; follow-up FC).
- **No delta-equivalent portfolio exposure** — needs an entry-delta join from `scans`; genuinely useful, deliberately deferred to a follow-up FC to protect this scope.
- **No bot strategy/gate changes.** Bot-side changes are limited to ingest: SPY benchmark bars + FEE activity ingestion.
- **No alerting/notifications** — flags render on the dashboard; push channels are a follow-up.
- No changes to the legacy log-sink pipeline; no frontend stack changes.

## Proposed approach

Four layers, deployable in order: SQL views → bot ingest → backend → frontend.

### 1. Data layer (`docs/bigquery/fc018_views.sql` additive + new `fc031_views.sql`)

**`fc018_per_symbol_scorecard`:**
- Add `open_put_count` / `open_call_count` (`COUNTIF(outcome='open' AND option_type=…)`) for correct position-state labels (tooltip: subject to activities-ingest lag).
- Add `open_option_premium` = Σ `premium_total` where `outcome='open'` (cash received on still-open short options — needed by reconciliation).
- **No "raw basis" column.** The cumulative `running_share_cost / running_shares` ratio is polluted by prior-cycle residuals (review F2) and must not be presented as basis. Open-lot basis is computed in the backend FIFO walk (§3).

**`fc018_vs_buy_and_hold_per_symbol`:**
- `price_at_start`: first close **on or after** `first_trade_date` (`ARRAY_AGG(close ORDER BY date ASC LIMIT 1)`), plus `price_at_start_date` and `price_now_date` columns; frontend flags when `price_at_start_date > first_trade_date + 5d` (late backfill silently re-bases B&H — review F18).
- **`wheel_mtm_pnl`** = `COALESCE(total_realized_pnl, 0) + IF(current_shares > 0, current_shares * price_now, 0)` — full market value add-back (cost already expensed in the cash ledger; review F1) with explicit zero for share-less symbols (review F12). Open option marks are layered on in the backend from live positions when available (review F13); the view column is labeled accordingly.
- `wheel_minus_bh` recomputed from `wheel_mtm_pnl`.

**New `docs/bigquery/fc031_views.sql`:** `fc031_monthly_option_cashflow` — net option cash by calendar month (+premium on opening sells, −cost on buy-to-close) split put/call, from `fc018_acb_timeline_per_symbol.net_premium_delta`; gross retained as a column for tooltips.

### 2. Bot side (ingest only)

- `src/data/stock_history_ingestor.py`: universe = traded symbols ∪ `BENCHMARK_SYMBOLS = ["SPY"]`. SPY bars double as the **independent trading-day calendar** for anomaly detection (review F7).
- `src/data/activities_ingestor.py`: add `FEE` to `ACTIVITY_TYPES` (normalizes like JNLC via the existing net_amount path). Fees become a first-class reconciliation component now (~$24 on paper; material at live go-live — review omission #4). XIRR flows remain JNLC-only.

### 3. Backend (`dashboard/backend/`)

**`services/returns.py`** (pure math, unit-tested; already scaffolded): `xirr` (bisection, negative-rate bracket, degenerate → None), `twr` / `twr_series` (GIPS chain-linking; flows attach to the *next* equity observation — handles non-trading-day deposits), `max_drawdown` on the TWR-indexed curve (% — deposits can't mask a drawdown) **plus flow-adjusted dollar drawdown** (review F10), `indexed_curve`, `annualize` (None under 90 days).

**`services/lots.py`** (new, pure): minimal FIFO walk over per-symbol OPTRD events → open lots `[{qty, price, buy_time}]` + `open_lot_basis_per_share`. This is the display-only subset of FC-020's designed algorithm (buys push, sells pop-FIFO with splits); closed-lot re-pairing stays FC-020. Unit tests cover AMD's overlap case, partial sells, unpaired sells (warn + skip).

**`services/bigquery.py`:**
- `get_cash_flows()` (JNLC), `get_fees_total()` (FEE).
- `get_portfolio_returns(current_nlv)` — XIRR/TWR/max-DD (% and $)/days-since-first-deposit. Live NLV **replaces** any same-date equity row (no zero-length sub-period — review F10); `nlv_source` label propagates to drawdown output when the terminal is stale.
- `get_equity_curve_indexed(days)` — wheel TWR index + SPY price index rebased to window start.
- `get_wheel_cycle_stats(days)` — **closed wheel cycles only**, with symbols that ever had overlapping share lots (timeline `MAX(running_shares) > 100`) **excluded and counted in an `excluded_overlapping` field** (their per-cycle rows are FC-020-mis-paired; aggregating them fabricates expectancy — review F3). Returns: closed count, win rate, avg win/loss, expectancy $, **open cycles count + their current MTM** (survivorship visible), and an FC-029 regime split (`opened before/after 2026-05-08`).
- `get_put_trade_stats(days)` — unassigned closed puts, reported **separately** (blending re-imports the per-contract-win-rate artifact — review F4): count, win rate, net P&L, % closed early, and **held-to-expiry assignment rate** = `assignments / (assignments + expirations)` (early closes excluded from the calibration denominator — review F5), with the raw counts in the payload.
- `get_reconciliation(current_nlv, live_positions)` — falsifiable residual:
  `residual = (NLV − Σ JNLC) − [Σ total_realized_pnl + Σ open_option_premium + Σ FEE + Σ live position market value (stocks + options, signed)]`
  This is ≈ 0 by accounting identity **unless** the BQ ledger disagrees with the broker (missed activities, paper-engine anomalies) — exactly what it must detect. Payload: every component, `share_count_mismatches` (view shares vs live shares per symbol — AMD surfaces here), `known_gaps` entries with `as_of`/`reason` (AMD ≈ −$1,594, FC-019), residual net of known gaps. Warn when `|residual − Σ known_gaps| > max($500, 0.5% NLV)`, **and** when a mismatch appears for a symbol not in known_gaps, **and** when a known-gap symbol's mismatch disappears (stale allowance) — review F6/F15. Threshold reviewed after a week of live residuals.
- `get_bot_anomalies()` — trading calendar from **SPY bars** (independent of the scheduler; a SPY-bar day with zero scans is a missed trading day even in total scheduler failure — review F7). Flags: gate 100%-block streaks ≥3 trading days vs 30d baseline; no orders ≥3 trading days while scans ran; zero-scan trading days (last 7); per-job ingest staleness (activities 2h market-hours, portfolio/stock bars 30h). `[{severity, code, message, since, evidence}]`.
- `get_drawdown_pauses(live_positions, threshold)` — reference price = **latest OPASN put strike** for the held symbol (what the bot actually compares against, per FC-029 — review F8); shares from **live** positions (view-vs-live mismatch → anomaly badge, not a pause row); consecutive-below-threshold days bounded at the lot acquisition date; card labeled "inferred from prices — not bot telemetry". Threshold from the bot's `/config` proxy (`call_drawdown_pause_threshold`) with env fallback, labeled.
- `get_premium_by_day` / summary: add net-cashflow fields; **remove** dead `win_rate`/`return_30d`; **delete `get_pnl_by_symbol` + its `/api/metrics/pnl-by-symbol` endpoint** (options-leg-only, contradicts reconciled numbers, no v2 consumers — review F17).
- `get_per_symbol_scorecard`: pass through new fields; compute per-symbol `wheel_mtm_pnl` merge with open-lot basis + live marks.

**`routers/v2.py`:** `GET /portfolio/returns`, `/portfolio/equity-curve`, `/cycle-stats`, `/put-stats`, `/reconciliation`, `/bot-health/anomalies`, `/bot-health/drawdown-pauses`, `/monthly-cashflow`. Portfolio/reconciliation/pause endpoints fetch live NLV + positions via the existing bot-proxy helper; on failure fall back to last equity row / view shares with `*_source` labels.

## Risks & mitigations

- **Convention slippage** (the F1 class of bug): every P&L formula in code carries a comment naming the convention ("net cash + market value; cost already expensed"); `tests/test_dashboard_reconciliation.py` reconstructs NLV from a synthetic activity stream and asserts the identity holds — a falsifiable end-to-end fixture, not just unit math.
- **XIRR/TWR edge cases:** exhaustive unit fixtures (single/multi deposit, withdrawal, non-trading-day flow, same-date terminal replace, negative rates, degenerate → None).
- **Reconciliation cry-wolf:** thresholds provisional; review live residuals for a week before trusting the warn state; known_gaps carries dates/reasons and mismatch-driven staleness checks.
- **Anomaly false positives:** SPY-bar calendar; conservative streak thresholds; every flag carries its evidence.
- **`wheel_minus_bh` semantics change:** relabeled "Wheel (MTM)"; release note shows AMD before/after (now computed correctly — the cash ledger already carries AMD's full loss; MTM adds live share value, which for AMD is $0 per Alpaca, mismatch badged).
- **View re-apply ordering:** additive `CREATE OR REPLACE`; SQL applied before code deploy (FC-019 procedure); frontend renders `—` for missing fields.
- **Scope creep:** stretch = per-symbol collateral-day Σ/Σ comparison; cuttable; banned-metrics list enforced at review.

## Post-implementation code review (2026-07-07)

An 8-angle adversarial code review of the implemented diff (before merge) surfaced 3 confirmed defects and a set of efficiency/reuse findings — all fixed in the follow-up commit:

- **Crash**: `get_wheel_cycle_stats`'s failure payload was missing fields the CycleStats contract promises; a BQ outage would have crashed the Overview page. Fixed (full-shape fallback + frontend guards).
- **Symmetry violation** (docs/CLAUDE.md Wheel Strategy Symmetry Principle): put-trade stats shipped with no call-side twin. Fixed: `get_option_trade_stats(option_type)` + `/api/v2/call-stats` + one `OptionStatsCard` for both legs — the call card calibrates the held-to-expiry **called-away rate vs the call delta band**, the post-FC-029 signal that matters most.
- **Dead badge**: `get_drawdown_pauses` never populated `share_count_mismatches`, so the AMD-anomaly badge could never render. Fixed.
- **Config mechanism didn't engage**: the bot `/config` didn't expose `call_drawdown_pause_threshold` or the delta bands, so the dashboard always fell back to parallel constants. Fixed: `/config` now returns all three; dashboard band/threshold sourcing is live with labeled fallbacks.
- **Efficiency**: OPTRD scans restricted to held symbols; drawdown-pause N+1 bars queries batched into one; reconciliation's two view queries merged and its live-proxy fetches parallelized; 60–300s TTL memos on slow-moving reads (lot bases, anomalies, monthly cashflow); BotHealth no longer double-fetches the 30d filtering window.
- **Single sources of truth**: `BENCHMARK_SYMBOL` env shared by ingestor and dashboard (the anomaly calendar and benchmark curve can't silently diverge); `_run_query(params=)` centralizes parameterized queries; live-proxy helpers reuse `routers/live.py` instead of re-implementing normalization; shared `Stat` tile component.
- Deferred with rationale: known-gaps/deploy-dates as BQ reference tables instead of Python constants (follow-up — current list is one dated, documented entry); exposing `stage_number` from `scans` for funnel ordering (needs schema verification against the live sink table); FC-020 consuming `lots.py`'s walk (noted in both files).
