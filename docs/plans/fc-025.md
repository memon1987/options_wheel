## Context

Same Alpaca paper-engine bug as FC-021 (AMD silent-exercise), surfaced for AMZN by FC-024's view rewrite. AMZN $240 put `AMZN260116P00240000` was sold 2026-01-12 for $73 premium and expired 2026-01-16 with AMZN at **$239.09 — $0.91 ITM**. Standard option settlement auto-exercises ITM puts at expiry, but Alpaca's paper engine silently settled the position without emitting OPASN/OPTRD records. Per `trades_with_outcomes` the put still has `outcome='open'` four months later — impossible since the contract has expired.

Behavioral evidence the silent assignment occurred (full reconciliation in [docs/investigations/amzn-reconciliation.md](docs/investigations/amzn-reconciliation.md)):

- **Jan 23** the bot sells `AMZN260130C00240000` covered call. Could not have done this without holding shares — `wheel_engine` requires shares ≥ 100 before selling covered calls.
- **Apr 22** OPTRD `AMZN −100 @ $240, net = +$24,000` followed by OPASN call. Strike-to-strike round-trip suggests cost basis was $240 — exactly the strike of the missing assignment.
- AMZN's `share_side_pnl` is currently inflated by exactly +$24,000 — the magnitude of the missing OPTRD-in leg.

Cross-symbol scan confirms AMZN is the only affected symbol (`SELECT * FROM trades_with_outcomes WHERE outcome='open' AND expiration < CURRENT_DATE()` returns only this one row).

## Goals

- Inject the missing `OPASN` + `OPTRD` pair as synthetic rows so the FC-018 scorecard, cycle view, ACB walk, Trade Log, and Phase Timing show the correct AMZN per-symbol attribution.
- Reuse the FC-021 prefix pattern (`activity_id LIKE 'synthetic-fc-025-%'`) for trivial audit/rollback.

## Non-goals

- **Not** building a corrections-table layer with overlay views — overkill for a second one-off fix. If a third silent-exercise occurs, graduate to a generic `tools/diagnostics/correct_silent_exercise.py` writer.
- **Not** fixing the upstream Alpaca paper-engine bug — out of our control. (Could file a support ticket referencing the order id.)

## Proposed approach

Insert two rows directly into `options_wheel.trades_from_activities`, mirroring FC-021's exact shape:

| activity_id | activity_type | symbol | underlying | qty | price | net_amount | transaction_time |
|---|---|---|---|---:|---:|---:|---|
| `synthetic-fc-025-amzn-2026-01-16-opasn` | `OPASN` | `AMZN260116P00240000` | `AMZN` | 1 | NULL | 0 | 2026-01-17 00:00 UTC |
| `synthetic-fc-025-amzn-2026-01-16-optrd` | `OPTRD` | `AMZN` | `AMZN` | +100 | 240.00 | −24,000 | 2026-01-17 00:00 UTC |

Sign convention (verified against the existing Cycle 1 OPTRD-in pair on 2025-11-07): put assignment → shares acquired → `qty = +100`, `net_amount = -24,000` (cash leaves the account).

The `synthetic-fc-025-` prefix makes the rows trivially identifiable. Mirrors FC-021's pattern.

## Critical files

- `options_wheel.trades_from_activities` (BQ table) — synthetic rows inserted
- No code changes — every downstream view sums or windows over `trades_from_activities`.

## Reuse

- FC-021's pattern (synthetic INSERT, audit query, rollback). No new infra.
- Existing FC-018/FC-019/FC-024 view stack picks up the correction automatically.

## Risks & mitigations

- **Risk:** Synthetic data contaminates the canonical raw table. *Mitigation:* `synthetic-fc-025-` prefix. Audit query: `SELECT * FROM trades_from_activities WHERE activity_id LIKE 'synthetic-%'` returns FC-021 + FC-025 rows. Removal: `DELETE FROM trades_from_activities WHERE activity_id LIKE 'synthetic-fc-025-%'`.
- **Risk:** AMZN's per-symbol total flips sign relative to current dashboard expectation ($26,206 → $2,279). *Accepted:* This is the entire point of the fix. The current value is wrong; the post-fix value matches the verified Alpaca activity feed.
- **Risk:** A future re-ingest from scratch loses the corrections. *Mitigation:* INSERT captured in `## Execution` below; the `activity_id` is REQUIRED and unique-keyed via the table schema, so re-running the INSERT errors cleanly on conflict.

## Rollout

3. Verify `wheel_cycles_from_activities` for AMZN now returns 2 rows, with the new Cycle 2 having `cap_gain = $0` (Jan 16 silent assignment + Apr 22 called-away both at $240).

Rollback: `DELETE FROM options_wheel.trades_from_activities WHERE activity_id LIKE 'synthetic-fc-025-%'`.
